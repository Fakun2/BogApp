# GitHub Project Board — BogApp

## Objetivo
Gestionar BogApp con un Project estilo Código Cuatro: backlog correlativo, prioridades, fases M0-M10, sprints, áreas, tamaños, fechas, dependencias y trazabilidad de release.

## Campos
- Status: Backlog, To do, In progress, In review, Review failed, Blocked, Done.
- Priority: P0, P1, P2, P3.
- Phase: M0, M1, M2, M3, M4, M5, M6, M7, M8, M9, M10.
- Area: Product, Frontend, Backend, Database, QA, Infra, Security, Observability, Billing, Legal, Sales, Support, Docs, UX, Release, Architecture, Integration.
- Type: Feature, Chore, QA.
- Size: S, M, L.
- Sprint: M0-M10.
- Start date y Target date.

## Política de trabajo
Dos desarrolladores toman issues en orden de prioridad y dependencia. Ninguna issue bloqueada entra a In progress. Todo PR debe citar código BOG-XXX y evidencia.
